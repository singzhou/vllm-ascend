# 2026-11-16 DSpark小词表概率采样适配

基线：`singzhou/vllm-ascend:030_naie_dev`，提交 `7f93f07236def39e26b491798c7c461a552c2b23`。
交付分支：`fg11991/vllm-ascend:030_naie_dev_greedy_fix`。

V1 DSpark 使用裁剪词表时，原实现即使配置 `draft_sample_method="probabilistic"` 也会退回 greedy。
本次接通草稿概率采样及 target 词表空间的概率缓存。默认仍为 greedy；target 的 temperature、top-p/top-k 和训练权重由原配置决定。

## 实现

- `vllm_ascend/spec_decode/llm_base_proposer.py::_sample_dspark_draft_from_logits`：
  在 Markov 修正后的小词表 logits 上，复用现有 `_sample_draft_from_logits` 采样，
  再映射 token，并用 `arange(K) + d2t` 将 q 散射到真实 target 词表宽度。
  返回的 token 已是 target ID，可直接回喂下一步 Markov head；概率 `q` 的表外列为零。
- 同文件 `_run_merged_draft`：将实际采样使用的 `q` 写入预分配的 `[request, step, target_vocab]` 缓存，避免逐步列表与 stack 同时占用两份缓存。
  展平时使用概率张量自身的维度，避免把 target 宽度误当成草稿宽度。
  `compute_draft_token_ids` 的 DSpark 概率入口使用同一个采样方法。
- disabled、全 greedy 和无 sampling metadata 的 profile 路径返回 `q=None`。
  部分配套 vLLM 版本在全 greedy 时返回原 logits；此处显式丢弃，避免把小词表 logits 当成 target 概率。
- 沿用现有 runner 的概率缓存和 standard rejection sampler。
  验证使用完整 target 分布 `p`，接受规则为 `min(1, p(x)/q(x))`，首拒后仍从归一化的 `(p-q)_+` 采样。
  target 在草稿词表外的概率质量保留，恢复采样仍能生成表外 token。

现有 `use_local_argmax_reduction`、heterogeneous vocab 与概率采样的不兼容检查保留。
LM-head TP 已返回完整草稿词表，继续沿用原有行补齐和裁剪逻辑，散射发生在裁剪之后。
概率缓存使用 fp32 时约占 `4 × batch × draft_steps × target_vocab_size` 字节，另有 runner 重排及小词表采样的临时张量。
Review 修复与最新硬件验证见 `adaptation_docs/2026-11-16_DSpark概率采样Review修复与上机验证.md`。

## 启用

在现有 DSpark `--speculative-config` 中增加或更新：

```json
{
  "draft_sample_method": "probabilistic",
  "rejection_sample_method": "standard"
}
```

请求温度大于零时，草稿按现有采样器的温度规则抽样并导出实际 `q`。
草稿采样器目前只处理 temperature；target 的 top-p/top-k 可以与草稿不同，验证必须使用各自实际分布。
全 greedy 请求继续走确定性选词。本次不改变默认选词策略，也不修改 SpecForge 训练。
