# MegaChunkGdn BF16 末状态修复与 910B3 复测

**修复通过。** 384 和 2048 token 两个压力样本的输出与末状态都通过 CPU FP64 和原生 FLA-NPU 对比。8 个真实输入长度和 4 组补充用例也全部通过。真实 2048 token 的单算子中位时延上升 1.45%，压力 2048 token 下降 2.81%。[修复提交](https://github.com/singzhou/xllm-ops/commit/44e774aca24cf474eaf99f9840e7ad9df42929c5)

A2/A3 BF16 的 `chunk_h` 将按 token 衰减从 K 移到 `V_new`。Cube 直接读取原始 K，Vector 将 FP32 残差乘上衰减后转为 BF16，沿用原有暂存区。输出阶段继续读取未衰减的残差。随后将 K 的读取和衰减系数的广播移到等待期间，重测的 14 组精度数据与第一次修复逐项一致。[旧版问题定位](state_diagnosis.md) · [Ascend C 内核改动](https://github.com/singzhou/xllm-ops/commit/44e774aca24cf474eaf99f9840e7ad9df42929c5)

## 构建与复现

参与 910B3 构建的 MegaGDN 源码和回归文件与推送版本逐项核对了 SHA-256。独立打包使用了先前构建中的两个空 INI 占位。最终重编前清理了算子生成标记和对象文件，并核对新包实际加载路径。 [内核哈希](state-opt-kernel-sha256.txt)

公开复测使用 [当前独立脚本](../../../mega_gdn_prefill.py) 和合成输入。
