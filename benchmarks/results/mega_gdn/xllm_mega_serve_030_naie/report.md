## 精度故障及处理

使用原始 xLLM `43fc82b8` 时，512 token 及更短的 14 条请求生成 token 全部一致。2048 token 的检索用例从第一个生成 token 就出现 NaN logprob 并触发 HTTP 400，4096 和 8192 token 的检索用例也复现了该问题。

从 TP2 捕获实际 GDN 张量后，在单卡重放 4 次，每次得到相同的非有限值计数。输入 Q/K/V、门控、beta 和初始状态均有限，FLA-NPU 对同一组输入的输出和状态均有限。将 xLLM 已量化的 KKT 矩阵直接交给 FP64 三角解，首块逆矩阵最大绝对值为 1。CPU 模拟 xLLM 的 16×16 幂级数和 16→32→64→128 递归拼接，在与内核相同的步骤回写 BF16，逐元素复现了硬件逆矩阵，最大绝对值为 593920。BF16 回写误差在级数的数值抵消和递归中放大，随后污染 W/U 和状态递推。1024-token 前缀已经出现非有限输出。[求逆根因及 CPU 对照](solver_root_cause.md)

接入层对逆矩阵做幅度校验，并检查注意力输出与末状态是否有限。失败时在写回 SSM cache 之前，使用原输入和原 FP32 初始状态回退到 FLA-NPU。设备端校验汇总为一次标量回读，计入接入版的首字耗时。原始 vendor 内核的求逆缺陷仍存在。最新分支的 128 个相关单测通过，覆盖高幅度但有限的逆矩阵、NaN 输出、Inf 状态和同 dtype 下的状态布局。

带回退的版本与基线在 22 个中英文贪心生成用例中输出 token 全部一致，两组都通过全部 10 个长上下文检索用例，最长 12288 token。两组均有两条短问答输出了额外解释，严格格式命中率同为 20/22。107 个生成 token 的 logprob 平均绝对差为 0.00273，最大为 0.0967，未出现 NaN 或 Inf。

补测混合输入长度，并发 4 和 16 各跑两轮。40 对请求的生成 token 全部一致，两组答案均命中预期，最长输入同为 12288 token。[混合并发精度记录](concurrent_precision.json)

逐 prompt token 的 teacher-forced logprob 也与基线自身的重复波动核对过。四个用例合计 12,823 个分数，Mega 对基线的平均绝对差为 3.23，最大为 33.23。基线同进程两次请求的平均绝对差为 3.09，最大为 32.05。两次基线启动间的平均绝对差为 3.10，最大为 35.05。这组逐 token 分数有较大的背景波动。生成一致性和检索通过率是本次模型级验收可直接比较的指标。[生成精度记录](precision.json) · [基线重测](baseline_logprobs_repeat.json)

## 服务设置

两组使用 Qwen3.8-27B BF16、MRV2、DSpark-7 greedy，TP4，最大模型长度 16384，调度 token 上限 4096，最大并发序列数 32。卡 0–3 开启 MegaGDN，端口 43128。卡 4–7 保持原路径，端口 43129。两组均为 `--gpu-memory-utilization 0.85`，关闭 Prefix Cache，以免重复请求命中 cache。

最初两组在相同的 TorchDynamo 图编译断言处失败。切到 eager 后还需修正隔离部署目录里的 CANN vendor 搜索路径。正式对比统一采用 eager、DSpark AV 关闭的配置。两组使用相同的部署和采样配置。

## 服务显存

两组均以 `--gpu-memory-utilization 0.85` 完成精度测试和 19 组首字压测，期间无 OOM。启动报告的可用 KV cache 为 Mega 36.66 GiB、基线 36.72 GiB。压测期间 `npu-smi` 整卡 HBM 采样的最高单卡占用分别为 59,603 / 65,536 MiB（90.95%）和 58,336 / 65,536 MiB（89.01%）。采样峰值相差 1.24 GiB，包含权重、缓存、运行时和分配器保留。该采样无法捕捉所有瞬时分配。0.85 用于估算服务内存和 KV cache 预算，整卡 HBM 还计入 CANN 和设备保留内存。
