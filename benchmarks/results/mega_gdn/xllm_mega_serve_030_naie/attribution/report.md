# MegaChunkGdn 首字时延归因

原始 Mega 内核在真实输入上仍更快。上次单算子对比计入布局和状态适配，使用合成输入，计时范围中没有后续接入版的数值校验、标量回读和失败重算。本次在同一张卡上逐项补齐这三项开销，并在同一组 TP4 卡上做流同步对照。

## 同一份张量的算子重放

使用 Qwen3.8-27B 的 BF16 本地 TP4 头配置，比较 FLA-NPU ChunkGatedDeltaRuleFwd 和已安装的 xLLM `43fc82b8`。输入包括两份从真实服务捕获的 `Q/K/V/g/beta/initial_state` 和一份同形状的合成输入。Q/K 已归一化，计入其余布局、state 转换、输出缩放以及对应变体加入的校验。每组预热后交错测 10 轮，每轮用 NPU Event 计 20 次调用，取单次耗时中位数。表中的“校验入队”执行设备端归约。“加回读”同时在每次调用中读取校验标量。“实际接入”在异常时执行 FLA-NPU 重算。

| 输入 | token | 校验通过 | FLA | 原始 Mega | 加校验入队 | 再加回读 | 实际接入 |
| --- | ---: | :---: | ---: | ---: | ---: | ---: | ---: |
| 合成 | 128 | 是 | 300.7 | 285.5 | 472.1 | 569.5 | 570.3 |
| 真实 TP2 | 128 | 否 | 297.7 | 288.9 | 477.2 | 579.0 | 805.7 |
| 合成 | 512 | 是 | 455.4 | 292.8 | 484.4 | 633.3 | 632.7 |
| 真实 TP2 | 512 | 否 | 453.2 | 291.5 | 480.0 | 622.8 | 1042.9 |
| 合成 | 2048 | 是 | 1029.8 | 499.8 | 576.3 | 876.2 | 877.8 |
| 真实 TP2 | 2048 | 否 | 1030.0 | 497.9 | 576.3 | 884.5 | 1870.3 |
| 真实 TP0 | 128 | 是 | 298.4 | 289.8 | 479.0 | 579.3 | 579.6 |
| 真实 TP0 | 512 | 是 | 454.1 | 286.1 | 472.0 | 616.2 | 616.7 |
| 真实 TP0，抓取时输入已含 NaN | 2048 | 否 | 1029.8 | 502.1 | 576.3 | 877.6 | 1870.9 |

单位为 µs。真实 TP0 的 512-token 输入通过校验，Mega 从 286 µs 加到 617 µs，超过 FLA 的 454 µs。输入全部有限的真实 TP2 2048-token 样本触发回退，原始 Mega 为 498 µs，校验入队增加约 78 µs，标量回读再增加约 308 µs，执行回退后达到 1870 µs。该例的 FLA 为 1030 µs。合成 2048-token 用例通过校验并保留约 15% 的接入优势。原始算子的异常输出仅在单卡重放中用于量耗时，服务一直保留有效性检查。[算子精度根因与样本核查](../solver_root_cause.md)

## 同卡 TP4 服务对照

物理卡 0–3 当时有其他容器的任务。本次在物理卡 4–7 上顺序运行基线和 Mega，沿用 BF16、eager、MRV2、DSpark-7 和 `--gpu-memory-utilization 0.85`。基线运行中的同步对照只在每层 FLA 后插入一次当前 stream 同步，计算与结果保持一致。每个用例预热后跑 6 轮。TTFT 从发送流式请求算到首个生成 token，表内样本不含 profiler 开启时的请求。

| 每条输入 token / 并发 | 基线 p50（ms） | 基线加同步（ms） | Mega p50（ms） | 单 rank 合计回退率 | 按层批至少一 rank 回退 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 128 / 16 | 532.1 | 564.1 | 606.1 | 9.4% | 24.0% |
| 512 / 1 | 272.5 | 286.0 | 314.6 | 9.6% | 26.4% |
| 2048 / 1 | 509.8 | 374.7 | 497.3 | 11.5% | 30.6% |
| 2048 / 4 | 1296.0 | 1403.9 | 1416.9 | 10.3% | 27.1% |
| 4096 / 1 | 812.0 | 867.6 | 1032.8 | 6.1% | 16.7% |
| 8192 / 1 | 1560.4 | 1681.1 | 1727.5 | 6.6% | 19.6% |
| 混合 / 4 | 1119.0 | 1120.6 | 828.5 | 10.9% | 29.1% |

4096 和 8192 token 单请求只加同步就分别增加 55.6 ms 和 120.7 ms，2048 token 并发 4 增加 107.9 ms。纯同步对照省去了实际 Mega 检查的设备归约和失败后的 FLA 重算。它只能衡量串行等待在该配置下对首字时延的影响。

Mega 在 7 组中有 5 组 p50 更慢。2048 token 单请求的基线分布波动较大。混合并发 4 本轮比基线快，两组实际 prefill 微批切分不同。之前经验中 128 token 并发 16 的 +79.5% 本轮测到 +13.9%，服务调度和采样波动会改变单个并发点的回归幅度。

服务器按每个 rank 的实际输入和结果独立决定回退。各 rank 合计有约 6%–12% 的 Mega 调用回退。以相同层号和批形状对齐四个 rank 后，16.7%–30.6% 的层批至少有一个 rank 回退。正常调用和失败调用均执行校验与标量回读。以上统计按请求完整窗口计数，期间包含完成首 token 后为该请求执行的其余少量步骤。

## 4096-token 请求的设备与 Host 时间线

对基线、基线加同步和 Mega 分别单独采集一个已预热的 4096-token 单请求。两次 prefill 的实际长度为 4090 和 6，合计每 rank 96 次 GDN。使用 Torch-NPU Level 1 采集，在容器内另起进程调用 `torch_npu.profiler.profiler.analyse` 解析。三个配置均取得四个 rank 的设备、CANN 和框架事件。

| TP0 指标 | 基线 | 基线加同步 | Mega |
| --- | ---: | ---: | ---: |
| FLA 主核次数 / 合计 ms | 96 / 91.4 | 96 / 91.1 | 8 / 13.4 |
| Mega 主核次数 / 合计 ms | 0 / 0.0 | 0 / 0.0 | 96 / 39.8 |
| 归因范围内的 `aclrtSynchronizeStream` 次数 | 0 | 96 | 96 |
| 同步或标量回读的 Host 范围合计 ms | 0.0 | 307.3 | 314.6 |

Mega 及其回退的两个主核加总为 53.2 ms，低于基线的 91.4 ms。96 次 Mega 标量回读均观察到 `aten::_local_scalar_dense` 和 `aclrtSynchronizeStream`。Host 阻塞时间包含先前已入队的工作，不能直接换算成新增 TTFT。基线同步对照提供了可独立测量的增量。以 TP2 的同一采样范围为例，基线设备 Free 为 33.3 ms（2.5%），加入同步后为 156.9 ms（11.1%）。Free 分布随 rank 和通信等待改变，采用独立服务计时判断实际首字增量。
