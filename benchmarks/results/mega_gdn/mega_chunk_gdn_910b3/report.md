# Ascend 910B3 · MegaChunkGdn prefill 性能对比

在 910B3 环境编译并安装了 xLLM `43fc82b8` 的 `mega_chunk_gdn`，原仓 **73 个算子测试全部通过**。12 组 BF16 输入中，核心 NPU kernel 总耗时加速 **1.58–2.28×**。TP4 的 2048 和 8192 token 用例在计入归一化、布局转换和下发空档后，单流分别加速 **1.58×、2.09×**。TP4 的 32–512 token 用例在同一口径下加速 **1.07–1.09×**。

## 比较边界

- **vLLM Ascend 基线**使用容器内实际分支 `030_naie_dev` 的 `93eaec4e35d510a76635c340a5e355cea827edb4`。910B3、PCP=1 且 FLA-NPU 可用时，prefill 通过 `DeviceOperator.fla_gdn_prefill` 调用 FLA-NPU A2 Phase6。Profile 中核心路径有一个 `ChunkGatedDeltaRuleFwd` 主 kernel，另有 gate cast、gate 转置和输出转置。
- **xLLM 候选**使用 `43fc82b8f9f1d3fca063c4410635f78422bdabba` 的原仓 `custom_ops_lib.mega_chunk_gdn` 绑定，计入该绑定的五个清零任务和输出乘以 `1/√128`。序列边界、mask 和 `num_matrices` 提前构建。基线的 chunk 大小为 64，候选为 128。[候选算子说明](https://github.com/Sinle4Cat/xllm-ops/blob/43fc82b8f9f1d3fca063c4410635f78422bdabba/docs/zh/mega_chunk_gdn.md)
- **核心范围**从已归一化的 Q/K、V、log gate、beta 和 BF16 初始状态开始，返回已应用 scale 的注意力输出和 `[B,Hv,K,V]` 末状态。两边所需的输入布局在计时前准备好。范围覆盖 chunk 内门控累加、KKT、下三角求逆、WY、状态递推和读出。
- **适配层范围**从卷积后的连续 BSND Q/K/V、已准备的 gate/beta 和模型配置中的 FP32 初始状态开始，返回注意力输出和可写回的 FP32 末状态。计入 Q/K L2 归一化、布局与 dtype 转换和 scale。候选用 BF16 计算并生成末状态，再转回 FP32。卷积、gate 生成、cache gather/scatter、输出归一化、decode 和服务均在测量边界之外。

## 实测结果

输入使用 Qwen3.8-27B 的头配置，BF16 Q/K/V 和 beta、FP32 log gate、K=V=128。TP1/TP4/TP8 表示单卡上模拟该分片的本地头数，Hk/Hv 分别为 16/48、4/12、2/6。使用物理 7 号卡，CANN 9.2.0、torch 2.10.0、torch-npu 2.10.0.post7、FLA-NPU A2 26.9.1+deva4a7958，vLLM 为 `ced6857afa0ea7b2e3f0846a62e1394e90f15607`。

## 正确性与数据校验

- 原仓 73 个测试覆盖 FP16/BF16、多种头数、变长序列和初始状态。
- 15 组适配层对比中，注意力输出的最大相对 RMSE 约 **0.546%**，最大绝对误差 **0.00098**。末状态的最大相对 RMSE 约 **0.473%**，最大绝对误差 **0.00862**。相对 RMSE 使用 `||actual − expected||₂ / ||expected||₂`。
- 对最多 512 token 的 6 组非零状态核心用例，使用 CPU FP32 逐 token 递推做独立核对。候选输出和末状态的最大相对 RMSE 分别约为 **0.442%** 和 **0.378%**。本次使用合成输入测量单次 prefill，跨次写回和读取状态时的模型级精度仍待验证。
- 校验了 profiler 的开始和结束记录、480 组设备采样和 CPU 标记的顺序、单卡单流和每组任务序列。设备侧由 ArgMax 预热标记分组，CPU 标记用于交叉验证。已移除本次原始 profiling 目录，保留分组耗时和 kernel 汇总。

## 复现

候选仅编译 `mega_chunk_gdn`，使用分支锁定的 CATLASS `1483c7d` 和 PTO-ISA `781ac0e`。算子包使用隔离目录安装。容器启动脚本先加载 xLLM 的 vendor 库，避免 FLA wheel 的启动钩子影响原仓绑定解析符号。

公开复测使用 [当前独立脚本](../../../mega_gdn_prefill.py) 和合成输入。
